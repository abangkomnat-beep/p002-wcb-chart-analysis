# Compose WCB Daily Analysis

อ่าน [references/output-contract.md](references/output-contract.md) แล้วใช้เอกสาร canonical ที่ระบุในนั้น

## ⚠️ อ่านก่อนใช้

- **ผู้ประกอบบทตัวจริงคือโค้ด** — `tools/build_daily_package.py` → `tools/article_builder.py` ทำงานแบบ deterministic ไม่มีการเรียกโมเดลภาษาในสายท่อ
  สกิลนี้ใช้เมื่อ **ร่าง/แก้/ตรวจด้วยมือ** และเป็นสัญญาที่โค้ดต้องทำตาม · **ถ้าเอกสารขัดกับโค้ด โค้ดคือความจริง**
- **ระบบมีข้อมูลรายวัน (D1) เท่านั้น** ⇒ ไม่มี H4/H1/M15 · ห้ามใช้ภาษาชี้จังหวะเข้าแบบ intraday
- **ตัวเลขแผน (จุดเข้า/จุดตัดขาดทุน/เป้าหมาย/อัตราส่วน) เล่าได้ในสไตล์ ② คนเดียว** (ผู้ใช้ปลดมติข้อ 14ก เมื่อ 2026-08-04) — สไตล์ ① และ ③ ยังไม่มี · ค่าต้องมาจาก `internal/trade-plan.json` ห้ามคำนวณเองในชั้นบทความ · ภาษาต้องเป็นเงื่อนไขระดับวัน ("เมื่อแท่งรายวันปิดใต้ …") · เกณฑ์เต็มอยู่ใน Contract ข้อ 3ก
- ⚠️ **ด่านปล่อยแผนรับเฉพาะผลตรวจ `pass` (ตั้งแต่ 2026-08-05)** และ `trade_plan` เลือกจุดตัดขาดทุน/เป้าหมายที่ผ่านเกณฑ์ตั้งแต่ต้นทาง หาไม่เจอ = `no_trade` · ที่ค่าเกณฑ์ที่ผู้ใช้ล็อกไว้ (RR 1.2 · 2026-08-05) มีแผนผ่านราว **22% ของวัน** ⇒ **บทความราวสี่ในห้าฉบับไม่มีหัวข้อแผน และนั่นคือพฤติกรรมที่ถูก ไม่ใช่บั๊ก** · ห้ามผ่อนค่าใน `config/risk_thresholds.json` เพื่อให้หัวข้อโผล่บ่อยขึ้น

## ลำดับทำงาน

1. ล็อก `instrument_type`, cutoff, timezone, data status, unit และ source field ก่อนเขียน
2. แยก facts, interpretations และ scenarios — **ห้ามเติมค่าที่ source ไม่มี**
3. เขียนหัวเรื่อง ≤12 คำ: `{สินทรัพย์} + กริยาสถานะ + ระดับ/ทิศที่เป็นประเด็น` ตามด้วยบรรทัดเวลาตัวเอียง
4. ประกอบตามโครง 4 ช่วง (ดูหัวข้อถัดไป) — **ไม่เพิ่มหัวข้อ เพิ่มได้เฉพาะย่อหน้าในช่วงเดิม**
5. ระดับที่อ้างในช่วง ③ ต้องใช้เลขชุดเดียวกับบล็อกช่วง ④ · เรียกทุกระดับเป็นภาษาคน ห้ามชื่อรหัส
6. สิ่งที่ไม่มีข้อมูล = **ตัดประโยคเงียบ** ห้ามเขียนอธิบายว่าทำไมไม่มี
7. ตรวจด้วย `tools/public_copy_validator` ก่อนถือว่าเสร็จ

## โครงบทความ (v3.2 · Voice v1.1)

```text
# หัวเรื่อง ≤12 คำ
*ข้อมูล ณ D เดือนย่อ ปี เวลา HH:MM น. (เวลาไทย)*

① ย่อหน้าเปิด 2 ย่อหน้า
   ประโยคแรกล็อกสูตร: วันนี้ ( D เดือนย่อ ปี ) {สินทรัพย์} เปิดตลาดที่ระดับ {open} {หน่วย}
   แล้วกริยาทิศทางจากคลังสำนวน · บริบทจาก evidence ราคาเท่านั้น
   ห้ามอ้างสาเหตุจากข่าวในช่วงนี้

② ปัจจัยจับตา (มีเฉพาะเมื่อมีข่าวยืนยันแหล่งได้)
   ประโยคแรกล็อกสูตร: สำหรับช่วงนี้ นักลงทุนจับตา{เหตุการณ์} เพื่อหาสัญญาณ{ผลต่อสินทรัพย์}
   หนึ่งย่อหน้า ไม่เกินสองประเด็น · ห้ามมีตัวเลขเด็ดขาด · ปิดท้ายด้วยเครดิตสำนักข่าว
   ไม่มีข่าว = ตัดทั้งช่วงแบบเงียบ ไม่มีหัวข้อว่าง ไม่มีประโยคแก้ตัว

## ข้อมูลเทคนิค (Technical Analysis)     ← heading เดียวที่อนุญาตในเนื้อ
   ร้อยแก้ว 2 ย่อหน้า: เหตุ ("จากโครงสร้างกราฟรายวัน…") → ผล ("สะท้อนว่า…")
   → เงื่อนไขสองทางบังคับครบขึ้นและลง ("หาก…จะ…" + "ในทางกลับกัน หาก…จะ…")

④ {ชื่อสินทรัพย์แบบเต็ม}:
   แนวรับ {s1} / {s2} / {s3} {หน่วย}
   แนวต้าน {r1} / {r2} / {r3} {หน่วย}
   (จบที่บรรทัดแนวต้าน — ไม่มีหมายเหตุ ไม่มี disclaimer)

กราฟ + caption ภาษาคน 1 บรรทัด (กราฟต้องอยู่ทุกฉบับ)
```

**ชุดหัวข้อ 9 ข้อของ v2 (`Market Snapshot`, `แนวคิดการซื้อขาย` ฯลฯ) เลิกใช้แล้ว**

## กฎที่ validator บังคับ (`tools/public_copy_validator.py`)

- **ความยาว 350–560 คำ** (เป้า 380–520) นับด้วย `voice_rules.count_public_words` — นอกช่วง = fail
- heading ในเนื้อมีได้หัวเดียว · **ห้ามตาราง markdown (ห้ามอักขระ `|`)** · ห้าม bullet
- denylist คำ robot 20 รายการ (`voice_rules.VOICE_DENYLIST`)
- เลขทุกตัวต้องเท่ากับ `round_half_up(ค่าดิบใน evidence)`: forex 4 ตำแหน่ง · BTC หลักร้อย + comma · เปอร์เซ็นต์ 2 ตำแหน่ง · RSI จำนวนเต็ม
  **ปัดครั้งเดียวจากค่าดิบ ค่าเดียวกันทุกตำแหน่ง ห้าม template คำนวณเลขใหม่**
- หัวบทความมีเฉพาะ field สาธารณะ (`title`, `symbol`, `instrument_type`, `cutoff_at`, `timezone`)
- ใช้ภาษาความน่าจะเป็น: "ประเมิน" "มีโอกาส" "หาก" "ตราบใดที่" · กริยาเลือกจากคลังสำนวนตามเงื่อนไข evidence
- ห้ามข้อความตรงกับ reference corpus ต่อเนื่องเกิน 10 คำ

## กฎรวมหลักฐาน

- เทคนิค A ของแต่ละ Set ถือ bias หลัก · B/C ยืนยันหรือลดน้ำหนัก **ไม่โหวตแบบนับเสียง**
- ใช้ระดับจากชุดที่อนุมัติแล้วเท่านั้น (`levels.approved_level_values`) · **ห้ามสร้างราคาเป้าหมายจากสายตา**
- แนวรับ = 3 ระดับใต้ราคาล่าสุดที่ใกล้ที่สุด เรียงใกล้→ไกล · แนวต้านกลับกัน · ปัดแล้วชนกันให้ข้ามไประดับถัดไป
- จำกัดอินดิเคเตอร์ 2–3 ตัวที่หน้าที่ไม่ซ้ำ — ระบบคำนวณจริง 5 ตัว: `sma20` `sma50` `sma200` `rsi14` `atr14`
- ข้อมูลไม่ถึงเกณฑ์ใน `config/minimum_bars.json` = ไม่คำนวณและไม่แสดงผล

## ผลลัพธ์ (โครงจริงของ `tools/build_daily_package.py`)

```text
output/<batch_id>/<asset>/
  public/    article.md · article.json · chart-daily.webp · meta.json
  internal/  raw.snapshot.json · normalized.market.json · technical.evidence.json
             level-map.json · news-log.json · source-log.json
             qa-report.json · license-report.json
```

- `public/article.json` ใช้ schema `schemas/article-voice-v1.schema.json`
- ด่านข้อมูลไม่ผ่าน = **ไม่มีโฟลเดอร์ `public/` เลย** ไม่ใช่เขียนแล้วติดป้ายห้ามเผยแพร่
- ด่านบทความไม่ผ่าน = ย้ายทุกไฟล์ไป `internal/rejected/`

หาก input gate ขาด `instrument_type`, cutoff, timezone, data status, unit หรือ source log ให้สร้างได้เฉพาะ internal draft ที่ติด `qa_status: BLOCK` และแจกแจง field ที่ขาด ห้ามระบุว่าพร้อมเผยแพร่
