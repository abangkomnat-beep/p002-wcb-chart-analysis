# Edit Financial Language

ด่านวิจารณญาณของ Agent 08 — ใช้ **ต่อจาก** `tools/language_review.py` ไม่ใช่แทน

> เปลี่ยน "วิธีพูด" ได้ แต่ห้ามเปลี่ยน "สิ่งที่บทความกำลังบอก"

**สกิลนี้ไม่มีกฎของภาษาใดอยู่ในตัว** — กฎภาษาอยู่ใน Locale Pack (`locale-<id>-financial-editorial`)
ใช้กับภาษาไหนก็โหลดแพ็กของภาษานั้น เพิ่มภาษาใหม่คือเพิ่มแพ็ก ไม่ใช่เขียนสกิลใหม่

## ก่อนเริ่มทุกครั้ง

```bash
python -m tools.language_review <บท.md> --locale th-TH
```

ต้องรู้ให้ครบก่อนแตะบท: `target_locale` · `language_baseline` version + สถานะ ·
`voice_profile` · `writer_profile` · contract version ของบท

- **ไม่มีผลรันแนบ = ถือว่ายังไม่ตรวจ** ห้ามอ่านด้วยตาแล้วสรุปเอง
- locale ที่ไม่มี baseline → `LOCALE_BASELINE_MISSING` **หยุด** ห้ามหยิบกฎภาษาอื่นมาแทน

## ทำอะไรได้ ทำอะไรไม่ได้

| แก้ได้ (ชั้นภาษา) | ห้ามแตะ (ชั้นสาระ) |
|---|---|
| เรียงประโยค · คำเชื่อม · ความยาว · คำซ้ำ | ตัวเลขทุกชนิด · ราคา · % · วันที่ · หน่วย |
| ศัพท์ระบบ → ภาษาคน | ค่า indicator · timeframe · แนวรับ/แนวต้าน |
| น้ำเสียง · การเปิด/ปิดเรื่อง · หัวข้อ | จุดเข้า · จุดตัดขาดทุน · เป้าหมาย · อัตราส่วน |
| การอธิบายแนวคิดให้เข้าใจง่ายขึ้น | ทิศ · ข้อสรุปเทคนิค · เงื่อนไข · invalidation |
| สำนวนที่เหมาะกับ locale | ข้อเท็จจริงข่าว · แหล่งอ้างอิง · **ระดับความมั่นใจ** |

**Certainty Guard** — ต้องรักษาความต่างของ: อาจ/จะ · มีโอกาส/ยืนยัน · หาก/เมื่อเกิดขึ้นแล้ว ·
จับตา/แนะนำซื้อ · สนับสนุน/รับประกัน

ยกระดับความมั่นใจขึ้นหรือลง = ผิดเท่ากับแก้ตัวเลข ไม่ใช่เรื่องสไตล์

## สี่โหมด — ดูสถานะ baseline ก่อนเลือก

| สถานะ baseline | โหมด | ทำอะไร |
|---|---|---|
| draft/calibrating/candidate | `CALIBRATION_REVIEW` | เสนออย่างเดียว ห้ามแก้ไฟล์ · **รวมทุกบทของวันถามครั้งเดียว** |
| (ผู้ใช้อนุมัติแล้ว) | `APPLY_APPROVED` | apply เฉพาะข้อที่อนุมัติ ผ่าน `language_patch` เท่านั้น |
| stable_locked | `STABLE_BASELINE_ENFORCEMENT` | ตรวจ deviation · ไม่ถามเรื่องที่ล็อกแล้ว · เจอกรณีใหม่ → `EXCEPTION_PROPOSAL` |
| (เห็นว่ากฎควรเปลี่ยน) | `BASELINE_CHANGE_PROPOSAL` | เสนอ → ผู้ใช้อนุมัติ → regression ผ่าน → bump version |

## รูปข้อเสนอ (ทุกข้อต้องครบ 4 ช่อง)

```
[L-0xx] <หมวด> · <ระดับ> · บรรทัด <n>
เดิม  : <ข้อความเดิมที่ยกมาตรงตัว — ต้องหาเจอในบรรทัดนั้นจริง>
เสนอ  : <ข้อความใหม่ — ตัวเลขและคำบอกความมั่นใจต้องครบเท่าเดิม>
เหตุผล: <อ้างกฎใน baseline ข้อไหน ไม่ใช่ "อ่านลื่นกว่า">
```

ข้อที่คิดคำแทนไม่ได้ ให้ปล่อย `เสนอ` ว่างและบอกว่าติดตรงไหน — **ห้ามเดาคำมาใส่**

## กติกาที่ห้ามละเมิด

1. **อนุมัติ 3 จุด = แก้ 3 จุด** ห้าม rewrite ทั้งบทเด็ดขาด แม้จะเห็นว่าทั้งย่อหน้าควรเขียนใหม่
2. **ห้ามแก้ไฟล์เอง** — เขียนผ่าน `python -m tools.language_patch` เท่านั้น เพื่อให้ผ่าน integrity และมี diff
3. **ห้ามคัดลอกประโยคจาก `approved-examples`** ไปวางในบทใหม่ — ใช้ดูรสนิยม ไม่ใช่คลังประโยค
   (ทุกบทเปิดเรื่องเหมือนกัน = สไตล์ A–G ตายทั้งชุด ซึ่งแพงกว่าประโยชน์ที่ได้)
4. **ห้ามเสนอซ้ำสิ่งที่ `rejected-examples` บันทึกว่าผู้ใช้ปฏิเสธแล้ว**
5. **ห้ามเป็น final QA ให้ตัวเอง** — Agent 05 ตรวจอิสระต่อเสมอ
6. **วันที่ผู้ใช้ไม่ตอบชุดอนุมัติ บทต้องเดินต่อโดยไม่แก้ภาษา** ห้าม block การผลิต

## เสร็จเมื่อ

locale ถูก · baseline version บันทึกแล้ว · integrity ผ่าน (Protected Content เปลี่ยน = 0) ·
validator เดิมยังผ่าน · diff แนบครบ · Agent 05 รับต่อได้
