# P002 Morning Editorial Command Specification v1

สถานะ: **พัฒนา command runner + schema + เทส P0 แล้ว 2026-08-14 · regression เต็มผ่าน**

## 1. ปัญหาและเป้าหมาย

P002 ต้องมีบททองคำอย่างน้อยวันละหนึ่งบท ขณะที่สินทรัพย์อื่นเปลี่ยนตามแผนงานและข่าวของแต่ละวัน การรันสินทรัพย์ทั้งหมดอัตโนมัติจะสร้างบทที่ผู้ใช้ไม่ได้เลือก เนื้อหาซ้ำ และความเสี่ยงชื่อไฟล์ชนกัน

เป้าหมายปัจจุบันคือผลิต `xauusd` อัตโนมัติวันละหนึ่งบท และเพิ่ม `wtiusd` Style D อัตโนมัติเฉพาะวันจันทร์ ให้ผู้ใช้เลือกสินทรัพย์อื่นก่อนรัน แยก “เขียนวันนี้” จาก “เฝ้าข่าว” ไม่ผลิตของนอกคำสั่ง และแสดงแผนทั้งหมดก่อนเริ่มดึงข้อมูล

## 2. กติกาบรรณาธิการที่อนุมัติแล้ว

| กติกา | พฤติกรรมบังคับ |
|---|---|
| ทองคำ | เพิ่ม `xauusd` เข้าแผนเสมอ และผลิตบทหลักเพียง 1 บทต่อวัน |
| น้ำมัน WTI วันจันทร์ | เพิ่ม `wtiusd` ต่อจาก `xauusd` อัตโนมัติ และส่ง Style D ไป `03-WTIUSD-Style-D` พร้อมภาพโครงสร้าง ระดับ และปฏิทินรายสัปดาห์ |
| เจ้าของบททอง | `author_slug: natthaphon-s` |
| สินทรัพย์อื่น | ผลิตเฉพาะรายการ `--write` ของเช้าวันนั้น |
| เจ้าของบทอื่น | `author_slug: world-class-broker-team` |
| เฝ้าข่าว | `--watch` อนุญาตให้ตรวจและเสนอหัวข้อ แต่ไม่อนุญาตให้สร้างหรือเผยแพร่บท |
| สินทรัพย์นอกคำสั่ง | ห้ามผลิตอัตโนมัติ |
| ข่าวเร่งด่วนนอกขอบเขต | เสนอและรอผู้ใช้อนุมัติ |
| บทข่าวเพิ่ม | ไม่เกิน 1 บทต่อสินทรัพย์ต่อวัน, เว้นอย่างน้อย 3 ชั่วโมง และไม่เล่าเหตุการณ์เดิมซ้ำ |
| เพดานช่วงทดลอง | บทข่าวเพิ่มรวมไม่เกิน 3 บทต่อวันทั้งเว็บไซต์ |
| ชื่อไฟล์ชน | ตราบใดที่ชื่อบทใช้สินทรัพย์+วันที่ ห้ามวางหลายบทของสินทรัพย์เดียวกันขึ้นเว็บในวันเดียว |

คำว่า “วัน” ใช้เขตเวลา `Asia/Bangkok` และแต่ละรอบต้องมี `run date` ชัดเจน

## 3. คำสั่งที่เสนอ

เพิ่มชั้นบรรณาธิการเหนือ `tools.run_daily`:

```powershell
python -m tools.run_morning `
  --write eurusd --write gbpusd --write btcusd `
  --watch usd --watch btc `
  --exclude nvda `
  --confirm
```

- `--write ASSET` สินทรัพย์อื่นที่ต้องผลิตบทหลัก ใช้ซ้ำได้
- `--watch TOPIC` สินทรัพย์หรือหัวข้อที่ให้ตรวจข่าว ใช้ซ้ำได้
- `--exclude ASSET` รายการงดสำหรับแผนและ audit log ใช้ซ้ำได้
- `--confirm` เริ่มผลิตหลังแสดงแผน หากไม่มีธงนี้ให้ preview อย่างเดียว
- `--date YYYY-MM-DD` รันย้อนหลัง/ทดสอบ; ค่าเริ่มต้นคือวันที่ประเทศไทย
- `--event-extra ASSET` อนุมัติบทข่าวเพิ่มจาก proposal id ในรุ่นถัดไป

วันที่ไม่เขียนสินทรัพย์อื่น:

```powershell
python -m tools.run_morning --confirm
```

วันอังคาร–ศุกร์ผลต้องเป็นทองคำหนึ่งบทเท่านั้น; วันจันทร์ต้องเป็น `xauusd` และ `wtiusd` ตามลำดับ ไม่ใช่รันสินทรัพย์ทั้งหมดตามค่าตั้งต้นของ `tools.run_daily`

## 4. รูปแบบข้อความตอนเช้า

```text
เขียนวันนี้:
- EURUSD
- GBPUSD
- BTCUSD

เฝ้าข่าว:
- USD
- BTC

งด:
- NVDA
```

ชั้นผู้ช่วยแปลงข้อความนี้เป็น CLI และแสดง preview ก่อนรัน หากรายการเดียวกันอยู่ทั้ง `เขียนวันนี้` และ `งด` ต้องหยุดและแจ้งข้อขัดแย้ง

## 5. Morning plan ที่ส่งให้สายผลิต

ตัว runner ต้องสร้าง `work/editorial/YYYY-MM-DD-morning-plan.json` ก่อนเรียกสายผลิต:

```json
{
  "schema_version": 1,
  "run_date": "2026-08-14",
  "timezone": "Asia/Bangkok",
  "write_assets": ["xauusd", "eurusd", "gbpusd", "btcusd"],
  "watch_topics": ["usd", "btc"],
  "excluded_assets": ["nvda"],
  "ownership": {"xauusd": "natthaphon-s", "default": "world-class-broker-team"},
  "gold_daily_limit": 1,
  "event_extra_per_asset_limit": 1,
  "event_extra_site_limit": 3,
  "event_min_spacing_hours": 3,
  "confirmed": true
}
```

จากนั้นเรียก `tools.run_daily --asset ...` เฉพาะ `write_assets` และส่ง `--skip-selection` จนกว่าชั้นคัดเลือกใบขึ้นเว็บจะรองรับหลายสินทรัพย์ตาม morning plan โดยตรง

## 6. ลำดับการทำงาน

1. รับรายการและ normalize symbol เป็นตัวพิมพ์เล็ก
2. เติม `xauusd` อัตโนมัติ และเติม `wtiusd` ต่อท้ายเฉพาะวันจันทร์ แล้วตัดค่าซ้ำ
3. ตรวจ symbol กับทะเบียนสินทรัพย์ของ `build_daily_package`
4. ตรวจความขัดแย้งระหว่าง `--write`, `--watch` และ `--exclude`
5. แสดงวันที่ รายการผลิต รายการเฝ้าข่าว รายการงด และเจ้าของบท
6. ไม่มี `--confirm` ให้หยุดโดยไม่เขียน output และไม่เรียก API ตลาด
7. เมื่อยืนยัน บันทึก morning plan และรันเฉพาะสินทรัพย์ในแผน
8. ตรวจ `author_slug` หลังผลิตทุกบท
9. คัดบททองคำ และบท WTI Style D ในวันจันทร์ พร้อมภาพทั้งสามประเภท; บทอื่นเข้าคิว `world-class-broker-team`
10. บันทึกผลต่อสินทรัพย์โดยไม่ให้ความล้มเหลวตัวหนึ่งดึงทั้งรอบล้ม

## 8. สิ่งที่ไม่ทำในรุ่นแรก

- ไม่หมุนสไตล์ตามชื่อวัน; เลือกตามสภาวะตลาด
- ไม่เผยแพร่อัตโนมัติ เพราะยังต้องผ่านผู้ใช้
- ไม่สร้างบทจาก `--watch` อัตโนมัติ
- ไม่แก้ระบบ slug ในงานนี้; เป็นงานแยกกับทีมเว็บ
- ไม่เพิ่มสินทรัพย์ที่ยังไม่มีในทะเบียนข้อมูล

## 9. ตัวชี้วัดช่วงทดลอง 14 วันทำการ

- รอบเช้าที่สร้างแผนสำเร็จอย่างน้อย 95%
- ทองคำออกครบ 1 บทในทุกวันที่ตลาดเปิดและข้อมูลผ่านด่าน
- บทผิดเจ้าของ = 0
- บทสินทรัพย์นอกคำสั่ง = 0
- ไฟล์ถูกทับจากชื่อชน = 0
- เก็บ returning visitors, เวลาอ่าน, scroll depth และอัตรากลับมาภายใน 7 วัน
