# WCB Daily Output Contract v3

Contract นี้เป็นแหล่งมาตรฐานเดียวสำหรับ XAU/USD, Forex และ Crypto โดยใช้คุณลักษณะร่วมจากตัวอย่าง 5 ภาวะตลาด: รีบาวด์, รอเหตุการณ์, Breakdown, ภูมิรัฐศาสตร์ และความต่างระหว่างทองโลกกับเงินบาท ตัวเลขสมมติในตัวอย่างห้ามนำมาใช้เป็นข้อมูลตลาดจริง

## 1. Input gate

ก่อนเขียนต้องมีข้อมูลหลังบ้านต่อไปนี้:

| Field | กติกา |
|---|---|
| `instrument_type` | ระบุชนิดจริง เช่น `spot`, `forex_spot`, `crypto_spot`, `futures`, `thai_gold_96_5` |
| `symbol` | ชื่อเครื่องมือที่ไม่กำกวม |
| `cutoff_at` | วันและเวลาตัดยอดแบบ ISO 8601 |
| `timezone` | เขตเวลาที่ใช้แสดงต่อผู้อ่าน |
| `data_status` | `live`, `delayed`, `preliminary`, `official_close` หรือ `locked_snapshot` |
| `unit` | เช่น USD/oz, quote currency, บาทต่อหนึ่งบาททองคำ |
| `source_log` | ค่า, source field/URL, published time, retrieved time และผู้ตรวจ |

ห้ามเรียก Futures ว่า Spot, ห้ามเรียกค่าประมาณทองไทยว่าราคาประกาศ และห้ามใช้คำว่า “ล่าสุด” หาก timestamp/status ไม่รองรับ

## 2. โครงสร้างบทความสำหรับผู้อ่าน

### ชุดหัวข้อ v3 (ผู้ใช้เคาะ 2026-08-03 — ใช้ชุดนี้กับบทความใหม่ทุกฉบับ)

```text
# พาดหัว
บรรทัดเวลา + Lead 3 ประโยค
## ภาพรวมตลาด
## ปัจจัยขับเคลื่อน
## มุมมองทางเทคนิค
## ระดับตัดสินใจ
## ฉากทัศน์
## เหตุการณ์ที่ต้องติดตาม
## มุมสำหรับผู้ลงทุนไทย   (แสดงเฉพาะเมื่อมีข้อมูล USD/THB หรือทอง 96.5% จริง)
## กราฟ
## ความเสี่ยง
```

ตารางเทียบกับชุด v2 เดิม ใช้เมื่อต้องอ่านบทความเก่าหรือย้ายเนื้อหา:

| v3 (ใช้ตอนนี้) | v2 (ชุดเดิมที่แช่แข็งไว้ใน `OUTPUT/`) |
|---|---|
| ภาพรวมตลาด | Market Snapshot |
| ปัจจัยขับเคลื่อน | ปัจจัยพื้นฐาน |
| มุมมองทางเทคนิค | วิเคราะห์ทางเทคนิค |
| ระดับตัดสินใจ | ระดับตัดสินใจ |
| ฉากทัศน์ | แนวคิดการซื้อขาย |
| เหตุการณ์ที่ต้องติดตาม | ข่าวและสิ่งที่ต้องติดตาม |
| กราฟ | ภาพและลิงก์ประกอบ |
| ความเสี่ยง | คำเตือนความเสี่ยง |
| มุมสำหรับผู้ลงทุนไทย | (ไม่มีใน v2) |

หัวบทความของ v3 มีเฉพาะ field สาธารณะ (`title`, `symbol`, `instrument_type`, `cutoff_at`, `timezone`)
ส่วน `qa_status`, `publication_clearance`, `data_status` และ field ภายในอื่นย้ายไปอยู่ `meta.json`

### รายละเอียดของแต่ละส่วน (เนื้อหาเดิมจาก v2 ยังใช้ได้ เปลี่ยนแค่ชื่อหัวข้อ)

### พาดหัว

ใช้สูตร `[ราคา/สถานะ] + [driver หลักไม่เกิน 2 เรื่อง] + [สิ่งที่ต้องจับตา]` หลีกเลี่ยงคำรับรองผลหรือพาดหัวเร้าอารมณ์เกินหลักฐาน

### Timestamp และ Lead

แสดง “ข้อมูล ณ [เวลา] [timezone] — [data_status]” แล้วเขียน 2–4 ประโยคให้ครบ:

1. เกิดอะไรขึ้น
2. เพราะอะไร โดยแยก fact จาก inference
3. วันนี้มองอย่างไร
4. ระดับหรือเหตุการณ์ใดเป็นจุดตัดสิน

### Market Snapshot

แสดงเฉพาะค่าที่ตรวจสอบแล้ว: ราคาปัจจุบัน/ราคาปิด, change และ %, Open/High/Low/Close ช่วงเดียวกัน, ช่วงแกว่ง และ cross-market drivers ที่เกี่ยวข้อง

- XAU/USD: เพิ่ม USD/THB, ทองไทย, DXY, yield, COMEX หรือ SPDR เฉพาะเมื่อมีข้อมูลจริงและระบุชนิดชัด
- Forex: เพิ่ม base/quote drivers, yield differential หรือ DXY เฉพาะคู่ที่เกี่ยวข้อง
- Crypto: เพิ่ม spot venue/reference, 24h range, volume/funding/open interest เฉพาะ source ที่รองรับ
- ห้ามแสดงแถวว่าง ห้ามประมาณค่าที่ contract ไม่อนุญาต

### สรุปตลาด

อธิบายลำดับราคา → จุดที่แรงซื้อ/ขายเปลี่ยน → ตลาดตอบสนองต่อ driver อย่างไร → ผลต่อ session ถัดไป ภายใน 1–3 ย่อหน้า

### ปัจจัยพื้นฐาน

แสดงปัจจัยหนุนและปัจจัยกดดันทั้งสองด้าน พร้อมกลไกส่งผ่าน เช่น ข่าว → ดอลลาร์/ยีลด์/กระแสเสี่ยง → สินทรัพย์ ห้ามสรุปเหตุเป็นข้อเท็จจริงจากการเกิดเวลาใกล้กันเพียงอย่างเดียว

### วิเคราะห์ทางเทคนิค

แยกหน้าที่ตามกรอบเวลา:

| ชั้น | หน้าที่ |
|---|---|
| Daily | แนวโน้มหลักและ market structure |
| H4 | momentum, breakout/rejection และระดับสำคัญ |
| H1/M15 | Trigger เท่านั้น ไม่กลับมุมมองใหญ่โดยลำพัง |

ใช้ผล Technical Set A/B/C โดย A เป็นแกนและ B/C เป็นตัวยืนยัน/ความขัดแย้ง จำกัด indicator 2–3 ตัวที่หน้าที่ไม่ซ้ำและไม่เกิน 5 ตัว หาก data field ไม่ versioned ให้รายงาน unavailable

### ระดับตัดสินใจ

แสดงแนวรับ, Pivot และแนวต้านพร้อมความหมายและวิธียืนยัน ใช้ zone เมื่อ volatility/precision สมควร ทุกระดับต้องอ้าง source field, timeframe และ timestamp ในข้อมูลหลังบ้าน

### แนวคิดการซื้อขาย

ทุกแผนต้องมี:

- `Bias`
- `Entry zone` เมื่อจำเป็น
- `Trigger`
- `Target`
- `Invalidation`
- `No-trade` หรือเงื่อนไขพัก

ใช้รูปแบบ Scenario เช่น Buy on Dip, Breakout, Sell Rejection, Breakdown หรือ Wait ไม่จำเป็นต้องมีทั้งขาขึ้นและขาลงหากหลักฐานไม่รองรับ ห้ามไล่ราคาเมื่อ Risk–Reward เสีย และต้องระบุเมื่อเป็นแผนสวนแนวโน้ม

### ข่าวและสิ่งที่ต้องติดตาม

- ไม่มีข่าวสดที่ยืนยันได้ใน 2 วันก่อน cutoff: `ยังไม่มีข่าวอัปเดตที่ยืนยันได้ภายใน 2 วันก่อน cutoff จึงใช้กราฟและระดับราคาเป็นหลัก`
- มีข่าว: ข่าวประกาศอะไร → กลไกส่งผ่าน → อาจส่งผลต่อสินทรัพย์อย่างไร → ต้องเฝ้าระวังอะไร จำกัดข่าวละ 2–3 ประโยค
- เก็บ publisher, URL, published/retrieved time และ counter-evidence ใน `source_log` ไม่ยัดรายการ monitoring ลงบทความ

### ภาพและลิงก์ประกอบ

กราฟหลักต้องมี symbol, instrument type, timeframe, cutoff timestamp, data status, ระดับตัดสินใจ, caption และ alt text กราฟเสริมมีได้เมื่ออธิบาย driver จริง เช่น DXY/yield, timeline ข่าว หรือ cross-market comparison ต้องไม่ตกแต่งระดับที่ไม่มีใน source

### คำเตือนความเสี่ยง

ใช้คำเตือนเฉพาะสถานการณ์ก่อน disclaimer มาตรฐาน เช่น event risk, gap, slippage, spread, leverage, false break หรือความต่างของทองไทยกับ Gold Spot และระบุว่าบทความเป็นข้อมูล/การศึกษา ไม่ใช่คำแนะนำเฉพาะบุคคล

## 3. ความยาวและน้ำเสียง

- วันปัจจัยน้อย: 450–650 คำไทย
- วันมีข่าว/กลไกสำคัญ: 700–1,200 คำไทย
- ใช้ภาษาความน่าจะเป็น: “ประเมิน”, “มีโอกาส”, “หาก”, “ตราบใดที่”, “ควรระวัง”
- อ่านรอบเดียวเข้าใจ: อธิบายศัพท์เทคนิคครั้งแรก ไม่แสดง indicator เพื่อโชว์จำนวน
- ไม่เลียนแบบวลีเฉพาะตัวของผู้เขียนต้นแบบ

## 4. Output package

| ไฟล์ | เนื้อหา |
|---|---|
| `article_draft.md` | บทความตามลำดับข้างต้น |
| `article_data.json` | facts, interpretations, scenarios และ missing fields |
| `chart_spec.json` | กราฟหลัก/เสริม ระดับ caption alt และ provenance |
| `source_log.json` | หลักฐานทุกค่าที่มีผลต่อพาดหัว/Lead/ระดับ/ข่าว |
| `article_meta.json` | symbol, cutoff, status, word count, clearance |

## 5. QA fail-closed

ให้ `BLOCK` เมื่อชนิดราคา/เวลา/source ของค่าหลักไม่ชัด, ข่าวไม่มีแหล่ง, กราฟไม่ตรงบท, ระดับหรือ Target ถูกสร้างเอง หรือคำเตือนสิทธิข้อมูลยังไม่ผ่าน ให้ `REVISE` เมื่อโครงสร้าง/ภาษา/ความยาวไม่ตรงแต่ข้อมูลยังตรวจสอบได้ ผู้ตรวจคนที่สองต้องทวนตัวเลขสำคัญทุกค่า ไม่ตรวจเฉพาะภาษา
