# WCB Daily Output Contract v3.1 (Voice v1)

Contract นี้เป็นแหล่งมาตรฐานเดียวสำหรับ XAU/USD, Forex และ Crypto — ตั้งแต่ v3.1
โครงบทความสำหรับผู้อ่านใช้ **โครงเล่าเรื่อง 4 ช่วงตาม WCB Voice Spec v1** (ผู้ใช้อนุมัติ
ระยะ 1 "ยกเครื่องภาษา" · CC ล็อก spec 2026-08-03) ส่วนกติกาข้อมูลหลังบ้าน (input gate,
source log, fail-closed) คงเดิมจาก v3 ตัวเลขสมมติในตัวอย่างห้ามนำมาใช้เป็นข้อมูลตลาดจริง

## 1. Input gate

ก่อนเขียนต้องมีข้อมูลหลังบ้านต่อไปนี้:

| Field | กติกา |
|---|---|
| `instrument_type` | ระบุชนิดจริง เช่น `spot`, `forex_spot`, `crypto_spot`, `spot_metal`, `stock_cfd`, `futures`, `thai_gold_96_5` — `stock_cfd` คือสัญญาอ้างอิงราคาหุ้น **ห้ามเรียกว่าหุ้นบนกระดาน** |
| `symbol` | ชื่อเครื่องมือที่ไม่กำกวม |
| `cutoff_at` | วันและเวลาตัดยอดแบบ ISO 8601 |
| `timezone` | เขตเวลาที่ใช้แสดงต่อผู้อ่าน |
| `data_status` | `live`, `delayed`, `preliminary`, `official_close` หรือ `locked_snapshot` |
| `unit` | เช่น USD/oz, quote currency, บาทต่อหนึ่งบาททองคำ |
| `source_log` | ค่า, source field/URL, published time, retrieved time และผู้ตรวจ |

ห้ามเรียก Futures ว่า Spot, ห้ามเรียกค่าประมาณทองไทยว่าราคาประกาศ และห้ามใช้คำว่า “ล่าสุด” หาก timestamp/status ไม่รองรับ

## 2. โครงสร้างบทความสำหรับผู้อ่าน

### โครงเล่าเรื่อง 4 ช่วง — v3.1 Voice v1 (ผู้ใช้อนุมัติระยะ 1 · CC ล็อก spec 2026-08-03)

มาตรฐานเดียว: **WCB Voice Spec v1** (`03-RR/Output/2026-08-03_WCB-Voice-Spec-v1.md`)
แม่แบบ: `templates/article-voice-v1.md` · ตัวประกอบ: `tools/article_builder.py`

```text
# หัวเรื่อง                       (≤12 คำ ไม่มีศัพท์รหัส — ชื่อสินทรัพย์ + กริยาสถานะ + ระดับประเด็นของวัน)
*ข้อมูล ณ D เดือนย่อ ปี เวลา HH:MM น. (เวลาไทย)*
① ย่อหน้าเปิด 2 ย่อหน้า           (ราคาวันนี้ + ทิศทาง · แล้วบริบทราคาย้อนหลังจาก context)
② ปัจจัยจับตา                    (เฉพาะเมื่อมีข่าวยืนยันแหล่งได้ — ระยะ 1 ไม่มีข่าว = ตัดทั้งช่วงแบบเงียบ)
ข้อมูลเทคนิค (Technical Analysis)  (ร้อยแก้ว 2 ย่อหน้า: เหตุ → ผล · แล้วเงื่อนไขสองทาง → กลยุทธ์)
④ บล็อกแนวรับ/แนวต้าน 3 ค่า        (v1.1: จบที่บรรทัดแนวต้าน — ไม่มีหมายเหตุ ไม่มี disclaimer)
กราฟ + caption ภาษาคน 1 บรรทัด   (กราฟต้องอยู่ทุกฉบับ — จุดขายของ P002)
```

**ส่วนขยาย v1.1 (คำสั่งผู้ใช้ 2026-08-04 หลังอ่านบทความจริง — CC อนุมัติ):**

1. **ตัดหมายเหตุ + disclaimer ออกจากบทความสาธารณะ** ("เอาออกไม่จำเป็นต้องเขียน") ทั้งสอง
   บรรทัดยังถูกบันทึกฝั่ง internal ที่ `internal/qa-report.json` → `omitted_public_lines`
2. **ขยายเนื้อหา** ("คุณต้องขยายความเนื้อหาให้มากกว่านี้") ด้วยวิธีเดียวที่อนุญาต — เพิ่มข้อมูล
   ลง evidence ก่อน (`article.json` → `context` และ `internal/technical.evidence.json` →
   `context`) แล้วจึงเล่าจาก evidence นั้น · หัวข้อไม่เพิ่ม เพิ่มเฉพาะย่อหน้าในช่วงเดิม
3. **เพดานความยาวใหม่ 350–560 คำ** (ดูข้อ 3)

เนื้อหาที่ v1.1 อนุญาตให้เล่าเพิ่ม (ทุกค่าอยู่ใน `context` และมีเทสกำกับรายตัว):
พฤติกรรมราคาย้อนหลัง (ปิดบวก/ลบติดต่อกันกี่วัน · จุดสูงสุด-ต่ำสุดของช่วง 20 และ 60 วันทำการ
พร้อมวันที่ · ระยะห่างเป็น %) · ตำแหน่งเทียบเส้นค่าเฉลี่ย (ห่างกี่ % · เส้นสั้นอยู่เหนือหรือใต้
เส้นยาว · เส้นชันขึ้นหรือลงเทียบ 5 วันทำการก่อน) · ความผันผวน (ช่วงแกว่งวันนี้เทียบค่าเฉลี่ย
14 วันทำการ) · โครงสร้างระดับ (ระยะถึงแนวรับ/แนวต้านแรกเป็น % · ตำแหน่งในกรอบ) ·
มุมมองเชิงกลยุทธ์แบบมีเงื่อนไข (ผูกเงื่อนไข evidence เดียวกับคลังหมวด จ.)

กติกาโครงสร้างที่ validator บังคับ (`tools/public_copy_validator.py`):

- heading ในเนื้อมีได้หัวเดียวคือ `ข้อมูลเทคนิค (Technical Analysis)` — ห้าม `##` อื่นทุกกรณี
- **ห้ามตาราง markdown** (ห้ามอักขระ `|`) · ห้าม bullet ในระยะ 1
- denylist คำ robot 20 รายการตาม spec ข้อ 3 (`tools/voice_rules.py` — `VOICE_DENYLIST`)
- เลขทุกตัวต้องเท่ากับ `round_half_up(ค่าดิบใน evidence)` ตามกติกาชนิดข้อมูล:
  forex ทศนิยม 4 ตำแหน่ง · BTC หลักร้อย + comma · เปอร์เซ็นต์ 2 ตำแหน่ง · RSI จำนวนเต็ม
  — ปัดครั้งเดียวจากค่าดิบ ค่าเดียวกันทุกตำแหน่ง ห้าม template คำนวณเลขใหม่
- สิ่งที่ระบบทำไม่ได้/ไม่มีข้อมูล = ตัดประโยคเงียบ ข้อความเชิงระบบทั้งหมดอยู่ฝั่ง internal

หัวบทความมีเฉพาะ field สาธารณะ (`title`, `symbol`, `instrument_type`, `cutoff_at`, `timezone`)
ส่วน `qa_status`, `publication_clearance`, `data_status` และ field ภายในอื่นย้ายไปอยู่ `meta.json`

ชุดหัวข้อ v3 (ภาพรวมตลาด/ปัจจัยขับเคลื่อน/มุมมองทางเทคนิค/ระดับตัดสินใจ/ฉากทัศน์/
เหตุการณ์ที่ต้องติดตาม/กราฟ/ความเสี่ยง) และชุด v2 (Market Snapshot ฯลฯ) เลิกใช้แล้ว —
เก็บไว้อ่านผลงานเก่าที่แช่แข็งใน `OUTPUT/` เท่านั้น

### รายละเอียดของแต่ละช่วง (ฉบับย่อ — ฉบับเต็มดู Voice Spec v1)

**หัวเรื่อง + บรรทัดเวลา** — สูตร `{สินทรัพย์} + กริยาสถานะ + ระดับ/ทิศที่เป็นประเด็น` ยาวไม่เกิน 12 คำ
ใต้หัวเรื่องคือบรรทัดเวลาตัวเอียง `*ข้อมูล ณ {D เดือนย่อ ปี} เวลา {HH:MM} น. (เวลาไทย)*`
เรื่องแท่งยังไม่ปิดรอบไม่อยู่ตรงนี้ — ย้ายไปเป็นหมายเหตุ 1 บรรทัดของช่วง ④

**ช่วง ① ย่อหน้าเปิด (2–4 ประโยค)** — ประโยคแรกตายตัว `วันนี้ ( {D} {เดือนย่อ} {ปี} ) {สินทรัพย์}
เปิดตลาดที่ระดับ {open} {หน่วย}` ตามด้วยกริยาทิศทางจากคลังสำนวน (ทิศตรงเครื่องหมาย change
ความแรงตามตาราง 2.6) บริบทที่เหลือมาจาก evidence ราคาเท่านั้น: เทียบราคาปิดวันก่อนหน้า (%),
จุดสูงสุด/ต่ำสุดระหว่างวัน — ห้ามอ้างสาเหตุจากข่าวและห้ามอธิบายว่าทำไมไม่อ้าง

**ช่วง ② ปัจจัยจับตา** — มีเฉพาะเมื่อมีข่าว/ปฏิทินที่ยืนยันแหล่งได้
ไม่มีข่าวที่ผ่านชั้นคัดกรอง = ตัดทั้งช่วงแบบเงียบ: จบช่วง ① แล้วเข้าหัวข้อเทคนิคทันที
ไม่มีหัวข้อว่าง ไม่มีประโยคแก้ตัว

**ส่วนขยาย v3.2 — ระยะ 3a เปิดใช้ช่วง ② แล้ว (คำสั่งผู้ใช้ 2026-08-04)**

ลำดับแหล่งข่าวตายตัว **เว็บ WCB ของเรามาก่อนเสมอ** แล้วจึง worldmonitor แล้วจึง RSS สาธารณะ
(`tools/news_source.py` · `config/news_sources.json`) — ข่าวล้มไม่หยุดสายท่อ ต่างจากราคา

กติกาของย่อหน้านี้:

- **หนึ่งย่อหน้า ไม่เกินสองประเด็น** ประเด็นซ้ำกันเล่าครั้งเดียว
- ประโยคแรกล็อกสูตร `สำหรับช่วงนี้ นักลงทุนจับตา{เหตุการณ์} เพื่อหาสัญญาณ{ผลต่อสินทรัพย์}`
- **เล่าได้เฉพาะ "ประเด็น" ที่มีในพจนานุกรม `themes`** — ไม่แปลพาดหัวข่าวตรงตัว ไม่สรุปเนื้อข่าว
  ประเด็นเดียวกันมีข้อความ "ผล" ต่างกันได้ตามสินทรัพย์ (`signal_overrides`)
- **ห้ามมีตัวเลขในช่วงนี้เด็ดขาด** เพราะเลขทุกตัวในบทความต้องชี้กลับค่าใน evidence ได้
  แต่ข่าวไม่ได้อยู่ในชุดนั้น ⇒ วงเล็บชี้ทิศ "(บวกต่อ…)" ของ spec **ยังไม่เปิดใช้ในระยะ 3a**
  จะเปิดได้เมื่อมีปฏิทินเศรษฐกิจที่ให้ค่าคาดการณ์เข้ามาเป็น evidence (ระยะ 3b)
- ปิดท้ายด้วยการเอ่ยชื่อสำนักข่าวเป็นเครดิต · ชื่อที่มีตัวเลขหรือมีคำใน denylist จะไม่ถูกเอ่ย
- ลิงก์ข่าวถูกเก็บใน `article.json` → `drivers.verified_news` (ระยะ 2 จะหยิบไปฝังในเนื้อ)
  และบันทึกการไล่แหล่งทั้งหมดไว้ที่ `internal/news-log.json`

**ช่วง ③ ข้อมูลเทคนิค (Technical Analysis)** — ร้อยแก้ว 1 ย่อหน้า 3 จังหวะ:
เหตุ (เปิดด้วย "จากโครงสร้างกราฟรายวัน..." + ข้อเท็จจริง 2–3 ข้อ: ราคาเทียบเส้นค่าเฉลี่ย 20/50 วัน,
RSI เทียบระดับกลาง) → ผล (เชื่อมด้วย "สะท้อนว่า/แปลว่า" + วลีสรุปกำลังซื้อขายตามเงื่อนไข evidence)
→ เงื่อนไขสองทางบังคับครบขึ้นและลง ("หาก...จะ..." + "ในทางกลับกัน หาก...จะ...")
ระดับที่อ้างทุกค่าใช้เลขชุดเดียวกับบล็อกช่วง ④ · เรียกทุกระดับเป็นภาษาคน (แนวรับสำคัญ,
จุดต่ำสุดเดิม, เส้นค่าเฉลี่ย 20 วัน) ห้ามชื่อรหัสทุกชนิด

**ช่วง ④ บล็อกแนวรับ/แนวต้าน** — รูปแบบตายตัวที่ผู้อ่านประจำหาเจอที่เดิมทุกวัน:

```text
{ชื่อสินทรัพย์แบบเต็ม}:
แนวรับ {s1} / {s2} / {s3} {หน่วย}
แนวต้าน {r1} / {r2} / {r3} {หน่วย}
```

(v1.1 ตัดบรรทัดหมายเหตุและ disclaimer ออกตามคำสั่งผู้ใช้ — บล็อกจบที่แนวต้าน
แล้วต่อด้วยกราฟทันที · ข้อความเดิมยังถูกเก็บไว้ที่ `internal/qa-report.json`)

แนวรับ = 3 ระดับใต้ราคาล่าสุดที่ใกล้ราคาที่สุด เรียงใกล้→ไกล · แนวต้านกลับกัน · ค่าเดี่ยวเท่านั้น
(ระดับโซนใช้ขอบด้านใกล้ราคา) · ปัดแล้วชนกันให้ข้ามไประดับถัดไป ห้ามขยับเลขหนีกันเอง

**กราฟ + caption** — วางหลังบล็อก ④ พร้อม caption ภาษาคน 1 บรรทัด กราฟต้องอยู่ทุกฉบับ

## 3. ความยาวและน้ำเสียง (Voice v1)

- ความยาวรวม **350–560 คำ** (เป้า 380–520) — ต่ำกว่า 350 หรือเกิน 560 = validator fail
  (v1.1 ยกพื้นจากเดิม 250–450 คำ เพราะผู้ใช้สั่งให้ขยายเนื้อหา — ฉบับ v1 อยู่ราว 259 คำ)
- ตัวนับคำ deterministic อยู่ที่ `tools/voice_rules.py` (`count_public_words`):
  token ละติน/ตัวเลขนับตรงตัว คำไทยประมาณจากความยาวอักขระ ÷ 4.5 (สอบเทียบกับ corpus
  4 ชิ้นแล้วล็อกด้วยเทส — เครื่องนี้ไม่มี PyThaiNLP และห้ามเพิ่ม dependency)
- ใช้ภาษาความน่าจะเป็น: “ประเมิน”, “มีโอกาส”, “หาก”, “ตราบใดที่”, “ควรระวัง”
- กริยา/วลีเลือกจากคลังสำนวน 34 รายการของ Voice Spec ตามเงื่อนไข evidence เท่านั้น —
  กริยา “แรง” ต้องมีตัวเลขรองรับตามตาราง 2.6 และทิศต้องตรงเครื่องหมาย change
- ไม่เลียนแบบวลีเฉพาะตัวของผู้เขียนต้นแบบ — ข้อความห้ามตรงกับ reference corpus
  ต่อเนื่องเกิน 10 คำ (ตรวจด้วย `voice_rules.find_corpus_overlap` ในเทส)

## 3ก. นักเขียนสามสไตล์ (เพิ่ม 2026-08-04 ตามคำสั่งผู้ใช้)

ผู้ใช้ทักว่า *"มีตัวเขียน 3 เทคนิค แต่ผลออกมาสไตล์เดียว"* จึงแยกเป็นนักเขียนสามคน
ทะเบียนอยู่ที่ `tools/writers.py` (`WRITERS`) เขียนจาก **evidence pack ก้อนเดียวกัน**

| # | นามปากกา | สไตล์ | โครงสร้าง | ความยาว |
|---|---|---|---|---|
| ① | ณธาร | รายงานตลาด | ร้อยแก้ว 4 ช่วงตามข้อ 2 หัวข้อเดียว — **ของเดิม ห้ามแก้ถ้อยคำ** | 350–560 |
| ② | กฤช | โครงสร้างราคา | หัวข้อย่อยเลขกำกับ · ป้ายตัวหนานำย่อหน้า · รายการโซน · **จุดเข้า/จุดตัดขาดทุน/อัตราส่วน เมื่อวันนั้นมีแผน** · ปิดด้วยสรุปเป็นข้อ | 380–760 |
| ③ | ปุณณ์ | จังหวะตลาด | ไม่มีหัวข้อย่อย · ประโยคสั้น · เปิดด้วยโมเมนตัม · ปิดด้วยรายการที่ต้องจับตา | 220–480 |

#### ประวัติของด่านนี้ — เปลี่ยนสองรอบใน 2026-08-05 อ่านให้ครบก่อนแก้

ระดับที่อนุมัติเฉลี่ย 5 ตัวกระจายถึง 2.6–3.9 ATR ⇒ เปลี่ยนเป็น **ค้นตัวแรกที่ผ่านเกณฑ์**
ทั้งจุดตัดขาดทุนและเป้าหมาย · หาไม่เจอ = `no_trade` ตั้งแต่ต้นทาง

**ผลลัพธ์ปัจจุบัน:** ด่านเปิดใช้งานจริงแล้ว · ผู้ใช้ล็อก `minimum_rr` = **1.2** เมื่อ
