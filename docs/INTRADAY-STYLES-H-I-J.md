## 1. หลักที่แยก H/I/J ออกจาก "เครื่องปั๊มสัญญาณ"

**1 Style = 1 Analysis Pack** — สไตล์จะถือว่าใช้งานได้ก็ต่อเมื่อมีครบหกชั้น
และทุกชั้นมีที่อยู่จริงในโค้ด ไม่ใช่คำสัญญาในเอกสาร:

| ชั้น | อยู่ที่ไหน |
|---|---|
| Indicator Logic | `tools/intraday_indicators.py` |
| State / Story Logic | `tools/intraday_{trend,breakout,pullback}_story.py` |
| Writer Contract | `tools/intraday_{trend,breakout,pullback}_writer.py` + `intraday_writer_base.py` |
| Visual Contract | `tools/intraday_renderer.py` |
| Explanation Contract | หัวข้อ "อ่านศัพท์ในบทนี้แบบเข้าใจง่าย" (บังคับทุกบท) |
| QA Contract | `intraday_writer_base.validate()` + `tests/test_intraday_*.py` |

**เส้นแบ่งที่ปิดตาย:** Python ตัดสินสถานะ · ตัวเขียนอธิบายสถานะ ·
**ตัวเขียนห้ามคำนวณ indicator ห้ามสร้างระดับราคาใหม่ ห้ามเปลี่ยนสถานะ**

## 2. ตารางสรุปสามสไตล์

| | H — แรงเทรนด์ระหว่างวัน | I — เบรกเอาต์ความผันผวน | J — ย่อแล้วไปต่อ |
|---|---|---|---|
| คำถาม | มีเทรนด์จริงไหม ฝั่งไหนคุม | บีบตัวหรือเบรกจริง | ย่อเพื่อไปต่อ หรือเสียแนวโน้ม |
| กรอบเวลา | M30 | M15 | M30 → M15 |
| Indicator | DMI/ADX · Supertrend · ATR | Donchian · BandWidth · ATR | Ichimoku · CHOP · ATR |
| โฟลเดอร์ | `H-แรงเทรนด์-M30` | `I-เบรกเอาต์-M15` | `J-ย่อแล้วไปต่อ` |
| ระดับที่ทำให้มุมมองเสีย | เส้น Supertrend | ขอบกรอบ Donchian | เส้น Kijun ของ M30 |

**หน้าที่ของ indicator แยกกันเด็ดขาด ห้ามให้โหวตทิศกัน:**
ตัวหนึ่งบอกสภาวะ · ตัวหนึ่งบอกทิศ · ตัวหนึ่งยืนยันแรง · ตัวหนึ่งวัดความผันผวน
ATR / ADX / CHOP / BandWidth **ไม่มีสิทธิ์บอกทิศ** — มีด่านเชิงกลบังคับข้อนี้ในบททุกใบ

## 3. สถานะของแต่ละสไตล์

```text
H   BULL_TREND · BEAR_TREND · EARLY_BULL · EARLY_BEAR · TRANSITION · NO_TREND
I   NORMAL · COMPRESSION · ARMED · BREAKOUT_UP · BREAKOUT_DOWN
    FAILED_BREAKOUT_UP · FAILED_BREAKOUT_DOWN · EXPANSION
J   NO_M30_BIAS · M30_BULL_CONTEXT · M30_BEAR_CONTEXT · PULLBACK_FORMING
    PULLBACK_CONFIRMED · PULLBACK_FAILED · TREND_RESUMED
```

สถานะกลุ่ม `FAILED_*` และ `TREND_RESUMED` นิยามด้วย **อดีต** ⇒ ต้องมีความจำสถานะ
(`state/intraday-<style>-<asset>-<timeframe>.json`) ถ้าไม่มีความจำ สถานะกลุ่มนี้เกิดไม่ได้เลย

## 4. โครงบทความ (เหมือนกันทั้งสามสไตล์)

```markdown
frontmatter (asset · title · excerpt · author_slug · timeframe · trend)
# พาดหัวที่สร้างจากสถานะ
*บรรทัดฐานข้อมูล — กรอบเวลา + เวลาแท่งปิด*
## 📌 สรุปสถานะรอบนี้          (สถานะ · กรอบเวลา · ระดับที่ทำให้มุมมองเสีย)
## 1. ภาพรวม…                  + ภาพที่ 1 + คำอธิบายภาพ + ย่อหน้าเชื่อมภาพกับข้อสรุป
## 2. หลักฐานการวิเคราะห์ทีละชิ้น + ภาพที่ 2 + คำอธิบายภาพ + ย่อหน้าเชื่อม
## 3. ระดับและเงื่อนไขที่ต้องจับตา
## 4. สัญญาณที่บอกว่ามุมมองนี้ไม่เป็นไปตามคาด
## 5. อ่านศัพท์ในบทนี้แบบเข้าใจง่าย
## 6. สรุปแนวโน้มรอบนี้
```

ความยาว **380–780 คำ** วัดด้วย `voice_rules.count_public_words`
(สูงกว่าเกณฑ์บทรายวัน 350–560 เพราะสามชั้นบังคับที่บทรายวันไม่มี — เหตุผลเต็มอยู่ในโค้ด)

**ภาพเป็นภาคบังคับสองใบต่อบท** — ภาพหลัก + แผงหลักฐาน
สไตล์ J ภาพหลักเป็น **M30** ส่วนแผงหลักฐานเป็น **M15** และชื่อไฟล์บอกกรอบของภาพใบนั้น

## 6. การผลิตแบบ State-driven

```text
ปิดแท่ง M15/M30 → คิดสถานะทั้งสามสไตล์ → เทียบกับความจำ
        ↓
สถานะเปลี่ยน (หรือรอบแรก) และมีเรื่องให้เขียน → ปล่อยบท
```

`tools/intraday_article_selector.py` ให้คะแนน **ความคุ้มค่าที่จะเป็นบทความ**
ไม่ใช่ความแรงของสัญญาณ — การเบรกที่ล้มเหลวได้คะแนนสูงพอ ๆ กับการเบรกสำเร็จ
ส่วน `NORMAL` และ `NO_M30_BIAS` ไม่ผลิตเลย เพราะบทที่บอกว่าไม่มีอะไรเกิดขึ้นไม่ใช่บทวิเคราะห์

**จำนวนใบต่อรอบขึ้นกับทางเข้า และความต่างนี้ตั้งใจ:**

| ทางเข้า | ใช้เมื่อไหร่ | ปล่อยได้ | ตัวเลือก |
|---|---|---|---|
| `intraday_pipeline.run()` | ยิงตามจังหวะปิดแท่ง | 1 ใบ (ที่เรื่องใหญ่สุด) | `select()` |
| `intraday_pipeline.run_round()` | รอบวัน (`run_daily`) | ทุกใบที่มีเรื่องให้เขียน | `select_all()` |

กติกา "หนึ่งใบต่อรอบ" แก้ปัญหาของ *การยิงถี่* — ถ้ายิงทุก 15 นาทีแล้วปล่อยสามสไตล์
พร้อมกันจะได้สามหน้าที่พูดถึงแท่งเดียวกันในนาทีเดียวกัน · แต่รอบวันเกิดวันละครั้ง
และวางไฟล์คนละโฟลเดอร์เหมือนที่ A–G ออกพร้อมกันทุกวันอยู่แล้ว ⇒ ข้อจำกัดนั้นไม่มี
เหตุผลรองรับในรอบวัน (และใบที่ขึ้นเว็บจริงยังถูกคัดวันละหนึ่งด้วย `publish_selection` อีกชั้น)

⚠️ **สิ่งที่ไม่ผ่อนคือเกณฑ์ "มีเรื่องให้เขียน"** — `worth = 0` และ `NEVER_PUBLISH`
ยังกันเหมือนเดิมทั้งสองทาง จำนวนใบต้องเพิ่มเพราะตลาดมีเรื่องเล่า ไม่ใช่เพราะลดเกณฑ์

**ธง `production` ในทะเบียน** คุมว่าสไตล์ไหนเข้ารอบวัน — `run_daily` ข้ามหัวข้อที่ไม่มี
สไตล์ใดเปิดอยู่ตั้งแต่ต้น ไม่ยิงดึงแท่งเปล่า ๆ · ปิดกลับทีละสไตล์ได้โดยไม่แก้โค้ด
· `--skip-style-hij` ข้ามทั้งรอบ

## 9. สไตล์ K (Volume/VWAP) ยังทำไม่ได้ — มีหลักฐาน ไม่ใช่ความเห็น

วัดปลายทางจริง 2026-08-13: WCB series API ส่งช่อง `v` มาเป็น **`null` ทุกแท่ง**
ทั้ง `interval=15min` และ `30min` ⇒ ไม่มี volume ให้ใช้ตั้งแต่ต้นทาง

และ validator ที่พิสูจน์ได้ว่า volume หมายถึงอะไร — ห้ามเรียก tick count ว่า traded volume

## 10. ป้ายเวลาแท่งไม่ใช่เวลาไทย — ✅ แก้แล้ว 2026-08-13 (เหลือรอคำยืนยัน E24)

วัดชี้ขาด 2026-08-13: `BTC/USD` กับ `XAU/USD` **เปิดแท่งใหม่พร้อมกันในวินาทีเดียวกัน**
(UTC 06:34:33/34) แต่ป้ายเวลาต่างกัน **10 ชั่วโมงเป๊ะ** (`06:30` กับ `16:30`)
⇒ เดินตามนาฬิกาโลกใบเดียวกันแต่เขียนป้ายคนละเขตเวลา และ**ไม่มีตัวไหนเป็นเวลาไทย**

`intraday_bars.parse_at` ประทับเวลาไทยให้ทุกป้ายโดยไม่ถามใคร ผลคือผิดคนละทิศ:

* **บิทคอยน์** (ป้าย ≈ UTC ⇒ เราอ่านเร็วไป 7 ชม.) — แท่งที่ยังก่อตัวดูเหมือนปิดนานแล้ว
  ⇒ **ด่านแท่งปิดถูกข้าม** ซึ่งเป็นด่านที่ทั้งระบบพึ่งพา
* **ทอง** (ป้าย ≈ UTC+10 ⇒ เราอ่านช้าไป 3 ชม.) — แท่งจริงที่ปิดแล้วถูกตัดทิ้ง
  ⇒ บทเขียนจากแท่งเก่ากว่าล่าสุดหลายชั่วโมงโดยบอกว่าใหม่สุด

**กระทบ F/G ที่อยู่ในสายผลิตอยู่แล้วด้วย** — ของใหม่แค่ทำให้เห็น เพราะกรอบ 15/30 นาที
ทำให้ความคลาดระดับชั่วโมงกลายเป็นเรื่องใหญ่ ส่วน 1–4 ชั่วโมงกลืนไปได้

### วิธีแก้ที่ใช้ (ผู้ใช้สั่งแก้เลย ไม่ต้องรอปลายทาง)

**ทะเบียนค่าที่วัดไว้ + วัดสดทุกรอบเพื่อตรวจทะเบียน** — ไม่ใช่ฝังตายตัวเฉย ๆ
(ผิดเงียบเมื่อปลายทางขยับ) และไม่ใช่ใช้ค่าที่วัดสดเป็นตัวจริง (พังตอนตลาดปิด)

| ชิ้นส่วน | ที่อยู่ |
|---|---|
| ทะเบียน offset ต่อหัวข้อ | `config/intraday_feed_timezones.json` |
| จุดแปลงเวลา (จุดเดียวในระบบ) | `intraday_bars.rows_from_candles` |
| ตัววัดสด · ตัวตรวจ | `intraday_bars.measure_offset` · `verify_offset` |

**แปลงที่จุดรับเข้า** เพราะทุกชั้นถัดไปเขียนบนสมมติฐาน "เวลาไทย" อยู่แล้ว
⇒ ทำให้สมมติฐานนั้นจริงตั้งแต่ต้นทาง ดีกว่าไล่แก้ทุกจุดที่อ่านเวลาแล้วพลาดจุดใดจุดหนึ่ง
· แถวเก็บป้ายดิบไว้ในช่อง `at_feed` ให้ตรวจย้อนได้ว่าแปลงมาจากอะไร

**กติกาตัวตรวจ** (ตั้งได้ในทะเบียน ไม่ต้องแก้โค้ด): ต่างไม่เกิน 1 ช่วงแท่ง = ปกติ
(ปลายทางเผยแพร่ช้าไม่กี่นาที) · ค่านอกช่วง −12…+14 ชม. = วัดไม่ได้ ใช้ทะเบียนต่อ
(ข้อนี้ทำให้เสาร์-อาทิตย์ของทองไม่พัง) · ต่างเกินที่ยอมและวัดได้จริง = **หยุดสายผลิต**

⚠️ **ค่าที่ใช้มาจากการวัดของเรา ไม่ใช่จากที่ปลายทางประกาศ** — ยังต้องส่งคำถาม 4 ข้อ
([รายงาน](../../../../01-CC/Output/2026-08-13_พบ-เขตเวลาแท่งระหว่างวันไม่ใช่เวลาไทย.md))
ถ้าเขาขยับฐานเวลา ด่านจะล้มให้เห็น ไม่ผิดเงียบ แต่บทจะหยุดจนกว่าจะวัดใหม่
